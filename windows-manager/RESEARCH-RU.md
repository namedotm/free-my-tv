## Удалённое управление (этап 5)

| Возможность | Статус в менеджере | Android 9 (проектор) | Android 11 (№1) | Android 14 (№2) | Ограничения |
|---|---|---|---|---|---|
| Подключить/отключить ADB, состояние авторизации | Реализовано | Да | Да | Да | Первое разрешение — только на ТВ |
| Кнопки пульта (`input keyevent`) | Реализовано | Да | Да | Да | Внедрённые нажатия минуют accessibility-фильтр Free My TV (кнопки Mi/YouTube это не проверяет) |
| Запуск приложения, системная карточка | Реализовано | Да | Да | Да | Только приложения со значком запуска |
| Снимок экрана (`screencap -p`) | Реализовано, проверено на №1 | Да | Да | Да | Защищённое видео (DRM, FLAG_SECURE) — чёрное; это защита, не ошибка |
| Экран в реальном времени и мышь (scrcpy) | Не встроено | scrcpy поддерживает API 21+ | Да | Да | Официальный scrcpy (Genymobile, Apache-2.0) — отдельная программа; встраивать её в ZIP без проверки версии и подписи не стал. Можно запускать рядом: `scrcpy -s IP:5555` |
| Передача файла в `Download`/`Movies` (`adb push`) | Не в интерфейсе | Да | Да | Да (scoped storage: только общие каталоги) | Используется для профиля ByeByeDPI; общая кнопка не добавлена |
| Открыть конкретный файл в плеере | Реализовано для SMB-файла (проверка медиатеки) | Да | Да | Да | Нужен MIME `video/*`; папку плееры не принимают |

Доступ извне домашней сети — отдельная задача: ADB, SMB и интерфейс менеджера наружу не
открываются, порты не пробрасываются, фонового агента нет.

## Загрузчик APK (этап 5)

`aapt2 dump badging` (Build Tools 34) читает манифест без запуска кода; `apksigner verify
--print-certs -v` проверяет подпись v1–v3 и даёт SHA-256 сертификата. Комплекты `.apks` (bundletool) и
`.xapk` распаковываются в `part-NN.apk`; все части обязаны иметь один пакет, versionCode и
сертификат. Для устройства выбираются base, feature- и языковые части, часть ABI под устройство и
ближайшая плотность экрана (`wm density`, на ваших ТВ — 320). OBB и зашифрованные APKM не
поддерживаются. Android 14 сам блокирует targetSdk < 23 — менеджер предупреждает заранее.

Проверено по официальным источникам 27.10.2026. Это технический анализ,
не аудит безопасности сторонних приложений и не тест на Xiaomi.

## SmartTube

- Официальный репозиторий и предупреждение:
  https://github.com/yuliskov/SmartTube#readme
- Зафиксированный последний stable-релиз на момент проверки:
  https://github.com/yuliskov/SmartTube/releases/tag/32.68s
- API releases/latest дал SHA-256 каждого APK; ссылки на VirusTotal в теле
  релиза содержат совпадающие хеши. Это данные разработчика, а не наша независимая
  антивирусная проверка. Утверждать «гарантированно безопасная сборка» нельзя.
- README сообщает об инфицировании среды разработчика, возможной компрометации
  ключей и восстановлении чистой среды. Нельзя считать старый сертификат сам по
  себе доказательством безопасности. Менеджер закрепляет конкретный файл
  post-incident релиза через официальный digest и проверяет подпись.
- На скачанном universal APK криптографически проверен сертификат
  109735aa24fe85e2e1623ebb3b1ecc4bf4263f4c6374e4411d646bfa2eda482a,
  package org.smarttube.stable. Это наблюдаемый сертификат официального артефакта,
  не отдельное независимое заверение нового ключа. Другой сертификат блокируется.
- Перед установкой latest сверяется повторно. Замена/удаление/обновление релиза
  требует новой проверки каталога. Использовать случайный APK или старый
  потенциально затронутый релиз нельзя.
- F-Droid упомянут в README как альтернативный способ распространения, но его
  иная подпись/пакет автоматически не смешиваются с GitHub stable.

## ByeByeDPI

Официальный проект: https://github.com/romanvht/ByeByeDPI
Зафиксирован релиз v.1.8.2. Подпись SHA-256 из официального README:
77451075acea406406475d74d459883a49a64051faf32e42f718f3f9777a8dfb.
Она совпала с подписью скачанного universal APK. Digest каждого ABI-артефакта
получен из GitHub release API и записан в catalog.json.

Исследованы:
- app/src/main/java/io/github/romanvht/byedpi/utility/SettingsUtils.kt
- app/src/main/java/io/github/romanvht/byedpi/data/AppSettings.kt
- app/src/main/java/io/github/romanvht/byedpi/activities/SettingsActivity.kt
- app/src/main/java/io/github/romanvht/byedpi/services/ByeDpiVpnService.kt
- app/src/main/res/xml/main_settings.xml и AndroidManifest.xml.

JSON имеет поля app, version, apps, settings; режим фильтра —
settings.applist_type="whitelist", список — apps, режим — byedpi_mode="vpn".
autostart и auto_connect установлены в false. Реальный VpnService при whitelist
вызывает Android addAllowedApplication для каждого выбранного пакета.
При пустом/недействительном списке Android может не ограничить VPN приложениями:
поэтому пустой профиль не создаётся и нельзя удалять все приложения активного списка.

Импорт реализован через FileActivity и пользовательский выбор разделов.
FileActivity не экспортирована; в manifest/source не обнаружен документированный
безопасный интерфейс headless-импорта JSON с ADB. Менеджер не пишет private data,
не вызывает скрытые интерфейсы, не использует run-as/root и не имитирует согласие VPN.
Профиль только копируется в общедоступный Download; импорт и подтверждение — на ТВ.

Поддержка TV/BOX указана автором, но конкретные Android 9/новые Mi Box, работа
пульта, Ethernet/Wi-Fi, параметры обхода у вашего провайдера и воспроизведение
YouTube требуют реального теста. Состояние VPN не устанавливается из успеха ADB.

## VLC, Vimu, MX, AirCast

- VLC 3.7.1: https://downloads.videolan.org/pub/videolan/vlc-android/3.7.1/
  Здесь опубликованы отдельные .apk.sha256 для каждого ABI.
  Криптографическая подпись официального arm64 APK проверена; SHA-256 сертификата:
  c8768d2cea0c4b622e419b4b4715981946821e4ebc035fb41776cad395a7f68e.
  Перед установкой выбранного ABI проверяется тот же сертификат и его собственный
  опубликованный SHA-256. Любое различие блокирует установку.
- Vimu: проверено официальное руководство https://vimu.tv/installation-guide.
  Оно направляет на https://vimu.tv/get, который по HTTPS перенаправляет на
  https://get.vimu.tv/installer/VimuInstaller.apk. Скачанный Installer:
  package net.gtvbox.installer, versionCode 112, minSdk 23;
  SHA-256 c3583e450ca0de36d90c764a9bebd97e0884be6cb9663e3a3f47c9d56936198a;
  криптографически проверенный сертификат SHA-256
  532f2ed32068eff138bdc2d3c0bfcad4bcfe5125df0f4fb7d26d9da4b62e7ff9.
  Отдельная опубликованная сумма не найдена: источник — HTTPS-сайт разработчика,
  наша сумма и сертификат фиксируют именно проверенный файл, а не являются
  независимым заверением ключа. Изменившийся файл автоматически не принимается.
  Installer устанавливается автоматически, установка плеера и активация — на ТВ.
  Руководство называет платную версию и Telegram Stars; Google Play показывает
  платное предложение. Это не основание считать скачивание Installer платным.
  Сам player net.gtvbox.videoplayer не подменяется Installer в статусе успеха.
- MX Player: официальная страница Google Play com.mxtech.videoplayer.ad.
  Для MX менеджер только открывает системный market URI по выбору пользователя. Покупка,
  региональная доступность и установка остаются у Google Play и пользователя.
- Общего документированного ADB-интерфейса записи SMB-паролей в эти плееры нет.
  Менеджер не редактирует private data приложений. Подключение SMB — в плеере.
- Для MX без SMB предлагается X-plore из Google Play, без автоматической установки.
- AirCast на проекторе сохраняется; автоматической установки AirCast на приставки
  нет, поскольку точное приложение/официальный источник и лицензия не подтверждены.
  Новых AirPlay-приёмников нет. Cast/Miracast не отключаются.

## Windows

- Переносимый Python: официальный пакет python из NuGet (издатель PSF),
  фиксированная версия и SHA-256 в dependencies.json. Лицензия включена в ZIP.
- Temurin JRE 17 Windows x64: официальный GitHub adoptium/temurin17-binaries;
  SHA-256 из опубликованного рядом файла .sha256.txt сохранён в dependencies.json.
- Android Build Tools 34 Windows: официальный Google repository2-1.xml содержит
  SHA-1 архива build-tools_r34-windows.zip. При подготовке он скачан по HTTPS и
  проверен по этой сумме; дополнительно закреплена SHA-256. При запуске проверяются
  обе суммы, проверка TLS не отключается. SDK автоматически не распространяется
  внутри нашего ZIP, а скачивается с Google при первой установке приложений.
- SMB использует штатные New-LocalUser/New-SmbShare/New-NetFirewallRule и NTFS
  ACL. Пароль вводится через Windows Forms в повышенном процессе, преобразуется
  в SecureString и передаётся New-LocalUser. Он не сохраняется в request/state/log.
  Учётные данные ОС управляются Windows, а не открытым файлом менеджера.
- UAC запрашивается штатным Start-Process -Verb RunAs. ExecutionPolicy Bypass
  не используется. Скрипты сохранены как UTF-8 BOM для Windows PowerShell 5.1.

## Диагностика по устройствам

Проектор: сохранить подпись/пакеты и проверить пропуск конфликтующего Free My TV;
не менять Ethernet, проекцию, автофокус, трапецию и выбранный Home.
Приставка №1: собственные API/ABI/версии/DRM/Cast и отчёт до/после.
Приставка №2: повторить независимо; не переносить выводы с первой коробки.
Везде только рекомендации, ни одного disable/uninstall/clear/reset/root.

Замер запуска VLC — только по отдельной кнопке, с предупреждением об открытии
приложения на ТВ. Без force-stop это может быть тёплый запуск. CPU/память/количество
процессов сохраняются до и после; сравнение не выдаётся за доказательство ускорения.


## INCY и UI-профили (новый выпуск)

Официальный сайт incy-app.com ссылается на INCY-DEV/incy-platforms. Его
RELEASE.json разделяет Android и Desktop. Проверена Android 3.8.1, её digest,
сертификат и LEANBACK_LAUNCHER; сведения закреплены в catalog.json. Публичный
репозиторий содержит публикации и манифесты, а не полный исходный Android UI.

Проверены официальные INCY-DEV/incy-docs:
- ru/dev-docs/app-management.md: per-app-proxy-enable, mode=proxy, list;
- subscription-format.md: HTTP-заголовки; per-app поля не поддержаны в body #;
- deep-links.md: импорт/подключение/status; connect/toggle менеджер не вызывает;
- tv-relay.md: зашифрованная передача ссылки с телефона на ТВ;
- app-management.md: hide-url может запрещать Share/Copy/QR/backup.

Поэтому не утверждается, что произвольная существующая закрытая подписка
автоматически клонируется с проектора. Есть установка клиента, подготовка
не-секретных параметров фильтра, открытие UI на приставках и точная инструкция
штатного переноса. Существующие защищённые сведения и ограничения экспорта
провайдера не обходятся.

Free My TV: добавлен ProfileInbox в процессе :home, доступный только UID 2000
или собственному UID. JSON имеет allowlist полей и размерный лимит. Секреты,
Home, разрешения и hardware-specific remotes отсутствуют. Применение проверяет
весь объект до записи; исходные значения изменённых полей сохраняются для
отката. Неподдерживаемый источник явно даёт PROFILE_UNAVAILABLE, без run-as/root.

W:\.intake: FolderInfo.ps1 читает тип диска в контексте обычного пользователя
Windows; сетевой mapped drive преобразуется в исходный UNC, а не перепубликуется
повышенным процессом. Для локального ресурса media.py показывает отдельные
server/share/subfolder/username/URI без пароля; скрытое имя папки не меняется.


## Доработка приложений и медиатеки

Проверен публичный исходный код VLC Android: StartActivity.kt, AndroidManifest.xml
и NetworkBrowserFragment.kt в https://github.com/videolan/vlc-android. ACTION_VIEW
обрабатывает SMB URI, но не является контрактом импорта сетевого источника и пароля.
Не используем extra_path как мнимый универсальный импорт. Для закрытых Vimu/MX
поддержка определяется экспортированным обработчиком установленной версии; если
его нет, требуются штатные действия на ТВ. Частные preferences/БД не записываются.

Предупреждение Wi-Fi находится в HomeMode.applyFree и wifiOwners: это защита
сохранённых сетей до отключения владельца. Повторная установка APK не меняет
владельца. Диагностика сохраняет только имена пакетов, не dumpsys wifi с SSID.
Удаление/отключение системных пакетов в менеджер не добавлено: HomeMode остаётся
единственным существующим механизмом его штатного переключения и отката.
