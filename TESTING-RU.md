# Xiaomi: первый тест сетевой кнопки

Изменение для Android: существующая круглая кнопка с иконкой Wi-Fi, подписью
«Настройки сети», навигацией стрелками/OK и штатным сообщением об ошибке.
Новых библиотек, служб и разрешений нет. HomeMode и Watchdog не изменены.
Порядок попыток: android.settings.NETWORK_SETTINGS → WIRELESS_SETTINGS →
WIFI_SETTINGS → SETTINGS. Последний вариант открывает общие настройки:
выберите сеть вручную. На Ethernet Wi-Fi-экран может не показывать проводную сеть.
Неизвестная или закрытая Activity пропускается; если не открылось ничего,
показывается штатное «Не удалось открыть…».

На существующей установке: Home Settings → Top Buttons → Network settings.
Сохранённый пользователем набор кнопок не перезаписывается.
Русский язык следует настройке телевизора или Home Settings → Language.
Остальные языки для новой подписи пока используют английский текст.
Изменение относится только к Android; webOS/Tizen в этот этап не входят.

## Сборка на Windows

Установите Git for Windows (Git Bash), JDK 17 и Android Studio SDK Manager.
В SDK Manager установите Android SDK Platform 34, Build-Tools 34.0.0,
Android SDK Platform-Tools. В Git Bash в каталоге этой изменённой копии:

```bash
export JAVA_HOME='/c/Program Files/Eclipse Adoptium/ВАШ-КАТАЛОГ-JDK-17'
export ANDROID_HOME="$(cygpath -u "$LOCALAPPDATA")/Android/Sdk"
./build.sh --generic
"$ANDROID_HOME/build-tools/34.0.0/apksigner.bat" verify --verbose --print-certs FreeMyTV.apk
python tools/translate.py --check
```

Укажите реальный каталог JDK. Нужен Python 3 только для проверки переводов.
Результат: FreeMyTV.apk. --generic не включает персональные API-ключи.
Сохраните freemytv.keystore отдельно и не публикуйте: следующие персональные
сборки должны иметь ту же подпись. Созданный скриптом ключ предназначен для
локальной разработки, его стандартный пароль не обеспечивает защиту хранения.
Windows-команды подготовлены по README, в облаке проверена Linux-сборка.

## До установки на работающий проектор

Не удаляйте Free My TV ради устранения конфликта подписей.
Не используйте автоматическую смену Home, очистку данных или downgrade (-d).
Сначала сохраните исходный APK и его сертификат. В PowerShell, с adb в PATH:

```powershell
$tv = '192.168.1.50:5555' # замените адресом своего устройства
adb connect $tv
adb -s $tv shell pm path io.freemytv
# Скопируйте путь base.apk из предыдущего вывода, без префикса package:
adb -s $tv pull '/data/app/ФАКТИЧЕСКИЙ-ПУТЬ/base.apk' FreeMyTV-before.apk
```

Проверьте оба APK через apksigner verify --print-certs (полный путь к
apksigner.bat в SDK/build-tools/34.0.0). Сравните SHA-256 сертификатов.
При разных сертификатах ОСТАНОВИТЕСЬ: этот APK не обновит установленный.
Для первого теста используйте запасное совместимое Android TV без Free My TV
или эмулятор Android TV. Отдельный package ID здесь не создаётся.
Резервный APK не содержит пользовательских данных; не считайте его полной
резервной копией. Если APK разделён на splits, сохраните все части.

Только после совпадения подписей и осознанного выбора установки:

```powershell
adb -s $tv install -r FreeMyTV.apk
adb -s $tv shell am start -n io.freemytv/.HomeActivity
```

Открытие Activity само по себе не требует менять системный Home.
Не включайте режим Free My TV заново ради теста кнопки: штатное переключение
также отключает ряд пакетов. Его аудит и подтверждение — отдельный этап.

## Ручная проверка

1. Пультом перейдите к кнопке сети; проверьте иконку, подпись и фокус.
2. Нажмите OK: открывается сеть или запасной экран настроек. Не меняйте сеть,
   чтобы не потерять Ethernet/ADB. Back возвращает в Free My TV.
3. Проверьте соседние кнопки, русский язык, обычное открытие приложений.
4. В эмуляторе/тестовой прошивке без сетевых Activity проверьте переход к
   общим настройкам; при отсутствии всех обработчиков — сообщение без сбоя.
   Не отключайте системные Settings ради этого теста на реальном устройстве.
5. Home Screen → Original и watchdog сохранены в исходниках, но их реальный
   откат не проверялся в облаке. Проверять переключение можно только после
   отдельного подтверждения его действий и доступности ADB на устройстве.

Откат интерфейса при совпадающем сертификате и допустимой версии:
`adb -s $tv install -r FreeMyTV-before.apk`. Если Android отказывает из-за версии,
не обходите защиту и не удаляйте приложение. Для возврата штатного Home
используйте Home Screen → Original на ТВ при работающем ADB; это отдельное
действие пользователя. Новый тестовый APK не подписан официальным ключом.

## Следующий этап: отдельная диагностика устройств

Никакие пакеты пока не признаны безопасными для отключения. Нет доступа к ТВ.
Для каждого устройства создаётся отдельный отчёт и отдельный журнал отмены.
До и после при одинаковой нагрузке сохраняются: getprop (модель/версия/API/ABI),
pm list packages -f, pm list packages -d, dumpsys meminfo, dumpsys meminfo io.freemytv,
dumpsys gfxinfo io.freemytv framestats, dumpsys cpuinfo, /proc/meminfo.
Сырые отчёты могут содержать персональные сведения — не публикуйте их целиком.
Измерьте одинаковые действия пультом три раза; сравните PSS, доступную память,
время запуска и кадры. Статистика кадров зависит от прошивки; обещаний ускорения нет.

| Устройство | Отдельный план |
|---|---|
| Projector 2 Pro, Android TV 9 | Сохранить текущий APK/подпись и состояние Home; проверить Ethernet и ADB; установить состав пакетов проекции/автофокуса/трапеции и защитить их; затем тест кнопки без смены Home. |
| Mi Box S EU №1 | Сначала определить модель, поколение, API, ABI и сборку; проверить Cast, DRM и воспроизведение, сохранить независимый отчёт. Не переносить список отключений с проектора. |
| Mi Box S EU №2 | Повторить диагностику независимо от первой коробки: одинаковое название не доказывает одинаковую прошивку. |
| Redmi G Pro 27U, HyperOS 2 CN | Сначала подтвердить наличие Android runtime, API ≥26, установщика APK, ADB и Activity настроек. Название HyperOS не доказывает совместимость. До этого установку и смену Home не планировать. |

Для будущего отключения требуется проверка назначения конкретного пакета,
его компонентов и зависимостей, явное подтверждение и запись исходного состояния.
Только для исходно включённого одобренного пакета: disable-user --user 0;
отмена: enable --user 0. Для состояния default восстанавливается default-state,
для исходно отключённого пакета состояние не меняется. Скриптов отключения пока нет.
Неприкосновенны Cast/AirPlay/Miracast, HDMI, настройки, изображение/проекция,
сеть/Bluetooth/звук, DRM, Play Services и безопасность. Root, удаление системных
APK и сброс исключены.

SmartTube (включая актуальное предупреждение разработчика о сборках),
проверка ByeDPIAndroid с allowlist только для SmartTube/YouTube,
AirPlay-приёмник и Windows SMB2/3 только на чтение — последующие отдельные
этапы исследования. Их совместимость и безопасность здесь ещё не проверены;
сторонних APK и глобального обхода в этой сборке нет.
